## 1. 运行方式

零依赖、无构建、无框架、无 CDN：所有资源都在本目录内，浏览器直接加载 ES modules。

```bash
# 方式一：任意静态服务器（推荐）
npm start                 # 等价于 python -m http.server 8099
# 打开 http://127.0.0.1:8099/index.html

# 方式二：Node
npm run serve:node        # 等价于 npx serve . -l 8099
```

**不要双击 `index.html`。** 浏览器对 `file://` 下的 ES module 有 CORS 限制，页面会白屏；
必须通过 http 打开（任意静态服务器均可）。

首次打开会自动生成"中等场景"演示数据，之后所有改动保存在浏览器 localStorage
（键名 `ppd-mvp-v1`），刷新不丢。右上角可备份/恢复 JSON、切换三套场景。

浏览器要求：Chrome / Edge 90+、Firefox 113+、Safari 16.4+。
`.xlsx` 导入用到原生 `DecompressionStream`（不支持的浏览器会提示改用 CSV 或 `.xls`）；
`.xls` 与 CSV（含 GBK）不依赖该 API。

`package.json` 里没有任何依赖，仅用于两件事：声明 `"type": "module"` 让 Node 能直接运行测试，
以及提供 `start` / `test` / `check` 三个脚本入口。

## 3. 关键规则如何落地

**排产（§4.4）**
- 硬约束先行：HC-01 工序顺序、HC-02 工作中心能力、HC-03 不可生产日期、
  HC-04 日产能超限、HC-05 下游数量超上游。存在硬约束时"确认计划"按钮被禁用。
- 产能按**物理量**占用：件/日模式按件数，工时/件模式按标准工时换算成工时，
  再与当日可用工时比较（`capacityPoolOf` / `capacityDemandOf`）。
  同一工作中心常承接标准工时不同的多道工序，若一律按"件"占用，会排出
  "账面不超产能、实际超工时"的计划；排产与 HC-04 校验共用这一对函数，
  因此两处结论始终一致。HC-04 按 (工作中心, 日期) 汇总后只报一条，
  结果与任务数组顺序无关。
- 软约束只提示不拦截：交期紧张、负荷不均、缓冲不足、未确认到料、到料晚于计划开工。
- 评分：九因素归入 交付 / 物料 / 产能 三桶加权（三套策略 60/20/20、25/60/15、30/20/50），
  再按优先级贪心逐日占用产能，**不承诺全局最优**（界面已明示）。
- 可复现：排产本身不含随机数与当前时间，同一输入两次排产结果一致。

**齐套（§4.3）**
- 两级 BOM 展开（产品 → 半成品/物料 → 原材料）。
- 五态：齐套 / 部分齐套 / 缺料 / 可齐套（待到货）/ 到货风险；整单按最差项（短板原则）判定。
- 可用库存 = 库存 − 其他订单已确认预留，确认预留时界面会提示对其他订单的影响。

**执行（§4.5）**
- 开工先过 G1（物料可支撑量）与 G2（上游已合格且未流转量）；完工申报受 G3 约束。
- 数量勾稽：订单已开工 = 首道工序累计开工；订单合格完成 = 末道工序累计合格。
- 所有申报都写入**报工履历（只增不改）**，页面底部可查，用于追溯与对账；
  因缺料被拒绝的开工尝试也会记入停工记录，供"缺料停工次数"指标使用。

**口径（§4.10）**
- 12 项指标在 `core/metrics.js` 里集中定义，每项都带 `formula`（公式）、`basis`（口径）、
  `detail`（明细），统计分析页可下钻。
- 仪表盘与统计分析共用 `defaultPeriod()`，避免同名指标出现两个数字。
- 分母为 0 时显示 `—` 而不是 `0.0%`（0.0% 会被读成"实际为 0"，真相是"没有样本"）。

## 4. 需要在验收时确认的两处口径解读

实现过程中发现方案原文存在两种读法，代码按下列解读实现，**并在界面口径说明里写明**，
请评审时确认或改判：

1. **准时完工率分母（D-03）**：原文"当期应交订单（含未完工）"。
   实现为"**应完工日已到期**（≤ 基准日）且落在统计期内的订单，含已到期未完工"。
   理由：未到期订单尚未构成"应交"，若计入分母，任何未来订单都会被预先算成未准时，
   指标会长期失真（实测可低至 5%）。
2. **部分齐套是否计入缺料**：`缺料订单数` 只统计"缺料"状态，部分齐套不计入，
   但会以"部分齐套"状态出现在物料页与异常中心。

## 5. 数据入口、场景与持久化

### 5.1 内置演示场景

| 场景 | 销售订单 / 生产订单 | 用途 |
|---|---|---|
| 简单 | 6 / 7 | 物料齐套、每工序单一工作中心，用于演示主流程 |
| 中等（默认） | 25 / 27 | 部分缺料、多工序、负荷接近上限 |
| 复杂 | 80 / 84 | 订单集中、到货延期、部分开工、替代中心、多异常并发 |

- 演示数据用固定种子生成，同一场景每次重建结果**逐字节一致**；生产订单同时包含
  "多对一（多行合并）"与"一拆多（拆批）"两种形态。
- 数据版本号 `SEED_REV` 写在数据里。若浏览器里存的是旧版本演示数据，
  顶栏会出现提示条，可一键重建，避免"半新半旧"数据导致数字看着不对。
- 该提示条**只对内置场景数据生效**（`seedRev` 非空且与当前版本不一致）；
  导入的外部数据不会被误判为旧数据，也就不会被"重建演示数据"误覆盖。

### 5.2 导入 Excel / CSV（推荐：合并，不清空）

**入口**：顶栏「导入」或基础数据页的「导入文件」。两者都打开同一个批量导入弹窗，
可一次选择多份文件；从基础数据页进入时会带上当前下拉选中的场景作为默认值。

**支持的文件**

| 格式 | 说明 |
|---|---|
| `.xlsx` | 浏览器原生解压 + 解析 XML，不依赖任何第三方库；支持共享字符串、内联字符串、多工作表 |
| `.xls` | Excel 97-2003（BIFF8）：自实现 OLE2 复合文档 + BIFF 记录解析，支持共享字符串跨 `CONTINUE` 分块 |
| `.csv` / `.txt` | 自动识别编码（UTF-8 / 带 BOM / UTF-16 / GBK-GB18030）与分隔符（逗号 / 分号 / 制表符） |

**一次导入多份、自动识别场景**
按工作表名、文件名、表头内容综合判断属于哪类数据（产品 / 物料 / BOM / 工作中心 / 工序适配 /
库存 / 到货 / 销售订单行 / 生产订单），识别结果可在预览表里逐份改成正确场景。
处理顺序按依赖固定为：产品、物料、工作中心 → BOM、工序适配、库存、到货、销售订单行 → 生产订单；
即使选择顺序颠倒，也能在同一批里"产品 + 销售订单 + 生产订单"一起导入。

**合并语义（不会误覆盖）**

| 数据类型 | 判重键 | 已存在时的行为 | 影响范围 |
|---|---|---|---|
| 产品 / 物料 / 工作中心 | 编码 | 覆盖更新，**保留原 id** | 只改本集合 |
| BOM 明细 | 产品 + 层级 + 子项 | 覆盖更新，不产生重复行 | 只改 BOM |
| 工序与工作中心适配 | 工作中心 + 工序名 | 覆盖更新 | 只改适配表 |
| 库存 | 物料 + 仓库 | 覆盖数量 | 只改库存 |
| 采购到货 | 物料 + 预计到货日 + 数量 | **跳过**（单据不覆盖） | 只改到货 |
| 销售订单行 | 销售订单行号 | **跳过**（单据不覆盖） | 只追加订单行，订单头按单号合并 |
| 生产订单 | 生产订单号 | **跳过**（单据不覆盖） | 只追加生产订单 |

- 因此"先导销售订单、再导生产订单"与"先导生产订单、再导销售订单"都不会互相覆盖；
  同一份文件重复导入是幂等的（主数据更新、单据跳过），不会堆出重复行。
- 生产订单允许只给「产品编号」而不填「销售订单行号」：系统会补一条占位销售行
  （单号 `SO-AUTO-<生产订单号>`，`auto: true`），让"单独导入生产订单"可用；
  若给的是不存在的销售行号，则整份文件报错并提示先导销售订单。

**表头与取值宽容**

- 表头可以在前 10 行内（真实报表常有"XX 数据（2026 版）"标题行）；
- 支持中英文别名（如 `产品编码` / `Item Code` / `productCode`），按别名识别时会在结果里提示；
- 数字容忍千分位；日期支持 `2026-12-01`、`2026/12/1`、`20261201` 与 Excel 日期序列号；
- 枚举容忍中文写法（`原材料`→`RAW`、`标准工时`→`STD_HOURS`），转换会在提示里写明。

**失败姿态**
每份文件独立成败：某份有错误只跳过该份，其余照常导入；错误给出**Excel 行号 + 字段 + 原因**
（如 `第 5 行 · 客户要求完工日：日期无法识别`）。校验阶段在库的副本上做，全部通过后才写库，
不会出现"一半新一半旧"。

**可追溯**
每条导入记录写入 `imp = { batch, file, at }`；批次汇总追加到 `importLogs`（保留最近 50 批），
在「场景 → 数据管理 → 导入履历」可查批次号、时间、文件、新增 / 更新 / 跳过条数。
导入弹窗默认勾选"导入前自动导出当前数据备份"。

**模板**
弹窗内可下载 9 类场景的空白模板（CSV，Excel 可直接打开填写），也可一次下载全部。

### 5.3 载入整库 JSON（替换全部数据）

用于测试数据集整体载入或备份还原，入口在「场景 → 数据管理」。

| 规则 | 说明 |
|---|---|
| 必填集合 | `productionOrders`（数组，可为 `[]` 表示只导入主数据） |
| 可选集合 | `products` / `materials` / `bomItems` / `routings` / `routingOps` / `workCenters` / `capabilities` / `downtimes` / `inventory` / `inbounds` / `salesOrders` / `salesOrderLines` / `orderLinks` / `planVersions` / `tasks` / `actuals` / `shipments` / `exceptions` / `freezeLogs` / `blockedLog` / `importLogs`；缺省补空数组 |
| 顶层信封 | 直接放数据集对象，或包在 `data` / `dataset` / `db` 里（兼容自身备份文件） |
| 编码解析 | `productCode` / `orderCode` / `workCenterCode` / `materialCode` / `versionCode` 自动解析成 id |
| 版本重连 | 缺 `planVersions` 时自动建 `PV-IMPORT`；`activeVersionId` 失效时自动修正；脱链任务改挂工作版本 |
| 校验粒度 | 必填、枚举、数字、日期（含 2 月 30 日这类"格式对但不存在"）、编号重复、关联存在性；错误给 `集合[下标].字段` |
| 失败姿态 | **任一条错误即整批不载入**，弹窗列出前 8 条并显示总数 |
| 覆盖行为 | **整库替换**：未出现在文件里的集合会变成空数组。只想增量补充数据时请用 §5.2 |

### 5.4 清空全部数据

- 入口：「场景 → 数据管理 → 危险操作」。
- 二次确认：必须先输入「清空」二字，按钮才可用；默认勾选"清空前导出 JSON 备份"。
- 清空后写入一个空库（而不是只删 storage 键），因此**下次打开不会自动重建演示数据**；
  顶栏出现"当前数据库为空"提示条，可直接导入 Excel/CSV 或载入演示场景。
- 空库下 10 个页面均可正常渲染（指标显示 `—` 而不是 `NaN`）。

### 5.5 数据归属与手工录入

- 所有数据保存在 `localStorage` 单键 `ppd-mvp-v1`，按"协议 + 主机 + 端口 + 浏览器 Profile"隔离。
- 手工录入（基础数据页「新增」、执行页报工、派工调整等）与导入数据写在**同一集合**里；
  合并导入只增改本文件涉及的记录，**不删除、不清空**其他记录，因此手工数据会保留。
- 主数据按编码更新时保留原 `id`，已引用该产品的生产订单、BOM、库存不会脱链。
- 需要"整体回到某个时点"时用 JSON 备份：备份/恢复是整库替换，与合并导入是两条不同的通道。

### 5.6 与 ERP / WMS 的对接现状

**当前只做文件级对接，没有系统集成**：

| 能力 | 现状 |
|---|---|
| 从 ERP 取数 | 导出 Excel/CSV 后导入（本版支持 xlsx / xls / GBK-CSV） |
| 向 ERP 回写 | 只提供导出：基础数据「导出当前表」、整库 JSON 备份；没有单据状态回写 |
| WMS 库存同步 | 通过库存模板 / 库存表导入，按（物料 + 仓库）覆盖数量；无实时接口 |
| 接口 / 账号 / 鉴权 | 无。当前是单用户本机应用，没有服务端与登录 |
| 扩展点 | 所有字段映射集中在 `io.js` 的 `IMPORT_SPECS`；要做 API 直连，在 `core/` 增加 adapter 复用同一套校验与合并函数，页面无需改动 |

因此，"连接 ERP/WMS"目前等价于"按模板导出 → 导入"，属于**批量、准实时**而非实时同步；
也没有增量水位、冲突检测与主数据版本管理。

## 6. AI 能力当前状态

方案中的 AI 分析**尚未接入**，当前为**降级态**：

- 异常详情页显示的"事实 / 推测 / 建议"由确定性规则模板生成，页头明确标注
  `规则摘要（AI 未接入）`，并区分"已知事实"与"推测"。
- 侧栏常驻显示 `AI：未接入（规则摘要）`。
- 该模块**只读不改数据**，不会自动调整计划或写入任何业务字段。

接入真实模型时，只需替换 `core/ai.js` 的实现，页面与数据结构无需改动。

算法侧覆盖：数量守恒（逐单逐工序）、排产可复现（三次一致）、三套策略输出可区分、

（数量 / 枚举 / 日期含非法日历日 / 重复编号 / 关联不存在）、编码→id 解析、
