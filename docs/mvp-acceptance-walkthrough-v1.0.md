## 1. 项目用途与核心模块

### 1.1 一句话定位

面向中小制造企业 PMC（生产计划与物料控制）的**单工厂、工序级按日排产**轻量系统，把「排产 / 缺料 / 报工 / 交付」四件事放进同一个数据模型，用一套可解释的规则跑通「计划—执行—偏差—复算」闭环。

**它不是什么**（测评时不要按下列能力去判缺陷）：

- 不是 ERP / MES，不做采购下单、财务、工时工资、设备联网；
- 不是最优化求解器，排产是**确定性启发式**，不承诺全局最优；
- 不是多用户协同系统，无账号、无权限、无审批流、无消息通知；
- AI 为**降级态**：异常详情的「事实/推测/建议」由规则模板生成，界面明确标注 `AI 未接入`。

### 1.2 核心模块

| # | 页面（导航名） | 核心职责 | 主要代码 | 测评关注点 |
|---|---|---|---|---|
| 01 | PMC 工作台 | 六类计数、今日任务、中心负荷、待处理异常、关键指标 | `ui/pages/dashboard.js` | 数字是否与其他页一致 |
| 02 | 订单管理 | 销售订单 → 生产订单（一拆多、多对一）、优先级维护 | `ui/pages/orders.js` | 拆批数量是否守恒 |
| 03 | 物料管理 | 齐套五态、物料预留、库存、到货、物料需求 | `ui/pages/material.js`、`core/rules.js` | 短板原则是否生效 |
| 04 | 生产排程 | 三套策略自动排产、甘特、硬约束拦截、逐工序调整、确认计划 | `ui/pages/schedule.js`、`core/scheduler.js`、`core/constraints.js` | 硬约束是否真的拦住 |
| 05 | 计划版本 | 版本快照/对比、模拟方案、应用为正式、冻结期与解冻留痕 | `ui/pages/versions.js`、`core/freeze.js` | 模拟方案是否污染正式计划 |
| 06 | 执行跟踪 | 开工/完工申报过三闸门、报工履历、批量导入 | `ui/pages/exec.js`、`core/execution.js` | 超量申报是否被拒 |
| 07 | 交付管理 | 日期链、五类延期识别、发货登记 | `ui/pages/delivery.js` | 日期链是否可追溯 |
| 08 | 异常中心 | 自动识别、去重、状态流转、规则摘要 | `ui/pages/exceptions.js`、`core/exceptions.js` | 重复扫描是否重复建单 |
| 09 | 基础数据 | 产品/物料/BOM/工艺/工作中心/工序适配/日历/停机/库存/到货 + CSV·XLSX 导入 | `ui/pages/base.js`、`io.js` | 导入校验是否给出行号 |
| 10 | 统计分析 | 12 项指标分组展示、公式与口径可查、明细下钻 | `ui/pages/stats.js`、`core/metrics.js` | 与工作台是否同一数字 |

**计算内核**（`app/assets/js/core/`，不依赖 DOM，可在 Node 中直接测试）：`constants`（口径单一来源）、`calendar`（工作日历）、`rules`（BOM/齐套/产能换算）、`constraints`（HC/SC 校验）、`scheduler`（评分+贪心排产）、`execution`（三闸门+履历）、`metrics`（12 项指标）、`exceptions`、`freeze`、`ai`、`store`、`seed`。

### 1.3 技术形态（决定了测评前提）

| 维度 | 事实 |
|---|---|
| 架构 | 模块化单体分层：展示层（`ui/`）/ 业务服务与规则层（`core/`）/ 持久层（`core/store.js`） |
| 依赖 | **0 个**。无 `node_modules`、无框架、无 CDN，断网可运行 |
| 构建 | **无**。浏览器直接加载 ES modules，改完刷新即生效 |
| 后端 | **无**。无接口、无数据库、无环境变量、无密钥、无埋点 |
| 存储 | 浏览器 `localStorage`，单键 `ppd-mvp-v1`，JSON 全量 |
| 代码量 | 约 7,300 行（JS/CSS/HTML），28 个 ES Module |

## 2. 运行或访问前提

### 2.1 三种访问入口

| 方式 | 地址 / 命令 | 适用场景 | 注意事项 |
|---|---|---|---|
| A. 线上演示 | <https://zoe-sofia.github.io/ppd-mvp/> | 快速看功能、不装环境 | 数据存在**测评机当前浏览器**，换机/清缓存即丢 |
| B. 本地克隆 | `git clone` + 静态服务器 | 正式测评（推荐） | 见 §2.3 |
| C. 自建 Pages | Fork 后启用 Actions | 需要自己的链接 | `pages.yml` 直接发布 `app/` 目录 |

> **测自己的数据**：三种入口都支持在系统内导入外部测试数据集（顶栏「场景：…」→「导入外部测试数据」），
> 不需要改代码或换部署。格式与行为见 §6.5。

### 2.2 环境要求

| 项 | 要求 | 说明 |
|---|---|---|
| 浏览器 | Chrome / Edge 90+；Firefox 113+；Safari 16.4+ | XLSX 导入依赖 `DecompressionStream`，不支持时只能走 CSV |
| Node.js | ≥ 18，**仅用于跑测试** | 运行系统本身不需要 Node |
| 网络 | 首次克隆需要；跑起来后**完全离线可用** | 页面不发起任何外部请求 |
| 屏幕 | ≥ 1366×768 | 排程页含甘特图与右侧调整面板，窄屏会横向滚动 |
| 端口 | 默认 8099，被占用时可换 | 换端口会导致 localStorage 数据"消失"（见 §3.2） |

### 2.3 启动步骤（本地）

```bash
git clone https://github.com/Zoe-sofia/ppd-mvp.git
cd ppd-mvp/app

# 方式一（推荐）
python -m http.server 8099
# 方式二
npx serve . -l 8099
# 方式三
npm start          # 等价于 python -m http.server 8099
```

打开 <http://127.0.0.1:8099/index.html>，首次进入自动生成「中等场景」演示数据。

**可选：跑一遍自动化校验，确认环境与代码一致**

```bash
cd app
npm run check      # 28 个 ES Module 语法门禁
npm test           # 31 项算法 + 49 项导入导出
```

预期输出：`通过 31 项，失败 0 项`、`通过 49 项，失败 0 项`。若失败，先排查 Node 版本与仓库是否被本地改动，**不要在测试红的情况下继续测评**。

### 2.4 【易错】三个前提误判

1. **双击 `index.html` 会白屏**。`file://` 下浏览器禁止 ES module 跨源加载，必须走 http。这不是缺陷。
2. **端口不是 8099 就不是同一份数据**。`localStorage` 按「协议+域名+端口」隔离，`127.0.0.1:8099` 与 `localhost:8099`、`8099` 与 `8100` 互不相通。
3. **换了浏览器配置（Profile）也看不到旧数据**。测评请固定一个干净 Profile，并在记录里写明。

## 3. 账号与权限

### 3.1 结论：本系统没有账号体系

无登录、无注册、无密码、无角色、无 Token。打开即用，所有人看到的是**当前浏览器里的那份数据**。

### 3.2 数据归属与隔离规则

| 规则 | 后果（操作人员必须知道） |
|---|---|
| 数据只存在当前浏览器的 `localStorage` | 换电脑、换浏览器、换 Profile、清缓存 → 数据全部丢失 |
| 同一浏览器内按 origin 隔离 | 换端口、换 host（`127.0.0.1` ↔ `localhost`）→ 视为两个系统 |
| 容量上限约 5MB（浏览器差异） | 复杂场景 + 大量报工后接近上限，保存会提示「本地存储可能已满」 |
| 无并发控制 | 两个标签页同时改，后保存的覆盖先保存的 |

### 3.3 测评前建议动作（3 分钟）

1. 用**独立的浏览器 Profile**（或隐身窗口 + 固定不关）作为测评环境；
2. 打开后先点顶栏「备份」，存一份 JSON 基线；
3. 在测评记录里写下：测评日期、浏览器及版本、访问地址（含端口）、数据场景。

### 3.4 【待确认】"权限"类测评项如何作答

由于设计范围明确不含权限体系（见 `app/README.md` §8），建议这样记录，避免被判为功能缺失：

> 权限与多用户：**不适用（设计范围外）**。系统为单用户本机工具，数据隔离依赖浏览器 Profile，不提供登录、角色与数据权限。若后续要多人使用，需新增服务端与认证，属架构性变更。

## 4. 主要业务流程

### 4.1 端到端主链路（建议按此顺序测评）

| 步 | 操作入口 | 动作 | 产出 / 可观察结果 |
|---|---|---|---|
| 1 | 基础数据 | 核对产品、物料、BOM、工艺路线、工作中心、日历 | 主数据就绪；BOM 两级、工序与中心适配正确 |
| 2 | 订单管理 › 销售订单 | 查看客户订单行、交期、数量 | 交期即「客户要求完工日」 |
| 3 | 订单管理 › 生产订单 | 由销售行「建立生产订单」（可一拆多） | 生产订单生成，状态 `待排产`；拆批数量之和 = 销售行数量 |
| 4 | 物料管理 › 齐套分析 | 查看五态与明细 | 整单按最差项判定；缺料项列出缺口与可开工日 |
| 5 | 生产排程 | 选策略 + 范围 →「执行自动排产」→ 看甘特与约束结果 | 生成工序级按日计划；硬约束有则「确认计划」禁用 |
| 6 | 生产排程 | 处理硬约束（调整工序改期/改中心）→「确认计划」 | 订单转 `已确认`，计划版本生效 |
| 7 | 计划版本 | （可选）复制为模拟方案 → 对比 → 应用为正式版本 | 旧正式计划转 `已失效`，新版本 `生效` |
| 8 | 执行跟踪 | 开工申报 → 完工申报（或批量导入报工） | 过 G1/G2/G3 三闸门；报工履历逐条留痕 |
| 9 | 交付管理 | 看日期链、识别延期 → 发货登记 | 实际发货日写入，交付风险可解释 |
| 10 | 异常中心 | 重新扫描 → 处理 → 标记解决/关闭 | 异常去重、状态可流转、必填处理说明 |
| 11 | 统计分析 | 选统计期与筛选 → 看 12 项指标 → 下钻 | 每个数字带公式、口径、明细 |

### 4.2 关键状态流转

**生产订单**：`待排产 DRAFT` → `已排产 SCHEDULED` → `已确认 RELEASED` → `生产中 IN_PROGRESS` → `已完工 COMPLETED` → `已关闭 CLOSED`；异常路径 `已取消 CANCELLED`。

**工序任务**：`未开始` → `进行中` → `已完工`；被改派/改期后回到未开始并重算。

**计划版本**：`正式计划 FORMAL` / `模拟方案 SCENARIO` × `生效 ACTIVE` / `已失效 ARCHIVED`。**同一时间只有 1 个生效版本**；应用模拟方案会把旧正式版本归档。

**异常**：`待处理 OPEN` → `处理中 PROCESSING` → `已解决 RESOLVED` → `已关闭 CLOSED`。已关闭的异常**不会被重新打开**，重复扫描只会命中未关闭项。

### 4.3 三条分支流程（容易漏测）

1. **缺料回退**：排产后发现缺料 → 调整到货或预留 → 重排该订单 → 齐套状态变化。
2. **冻结期改动**：基准日起 3 天内（默认）的任务不可直接改；确需改要走「解冻」，**必须填原因并留痕**。
3. **计划对比**：模拟方案与正式版本对比交付/物料/产能三个维度的差异，再决定是否应用。

## 5. 界面操作步骤（逐页）

> 通用交互：左侧导航 10 项（支持键盘 Enter/Space）；顶栏为「基准日 / 场景切换 / 备份 / 恢复」；列表页多为「筛选 + 表格 + 行内操作」；弹窗底部为「取消 / 确定」类按钮。

### 5.1 PMC 工作台

- **看什么**：6 个 KPI（在制订单、待排产、生产中、物料短缺订单、产能冲突、交付风险订单）、今日任务表、工作中心负荷条、待处理异常、关键指标 4 项。
- **可点**：KPI 卡片 → 跳对应页面；「查看排程」「甘特图」；「重新扫描」异常；「进入异常中心」。
- **验收点**：KPI 数字与目标页一致；「产能冲突」应为**按硬约束 HC-04 实时推导**，不是历史遗留字段。

### 5.2 订单管理

- **页签**：生产订单 / 销售订单。
- **操作**：关键词搜索（订单号/客户/备注）、状态筛选、「重置」；行内「详情」（含关联销售行、齐套、评分明细、任务列表）、「优先级」（改人工优先级）；销售订单页「建立生产订单」。
- **预期**：一拆多时校验「拆批合计 ≤ 销售行剩余数量」；已全部拆完的销售行不再可拆。

### 5.3 物料管理

- **页签**：齐套分析 / 物料预留 / 库存 / 到货信息 / 物料需求。
- **操作**：选订单看齐套明细 →「确认建议预留」；到货页「登记到货」。
- **预期**：五态判定取最差项；确认预留时提示**对其他订单可用库存的影响**；可用库存 = 库存 − 他单已确认预留。

### 5.4 生产排程（测评重点）

- **控件**：排产策略（交付优先 / 物料优先 / 产能优先，页面显示三桶权重）、订单范围（`仅未排产订单（推荐）` / `全部可排产订单（重排）`）。
- **流程**：`执行自动排产` → 看计划表与甘特（45 天窗口，周末/假日底色）→ 看约束结果表 → 有硬约束时点行内「调整」改期/改中心 → 「确认计划」。
- **预期**：
  - 硬约束（HC-01~05）存在时「确认计划」**不可点**；软约束（SC-01~05）只提示；
  - 调整弹窗保存前**重算约束**，仍违规则拒绝保存；
  - 冻结期内任务拒绝直接改；
  - 同一输入重复排产结果一致（可复现）。

### 5.5 计划版本

- **操作**：「复制为模拟方案」「应用为正式版本」「设为工作版本」「放弃」；右侧「计划冻结」改冻结天数（0~10）并保存；解冻列表逐条「解冻」（填原因）。
- **预期**：应用模拟方案后旧正式版本变「已失效」；版本对比给出交付/物料/产能差异；解冻写入日志。

### 5.6 执行跟踪

- **结构**：订单级进度（已开工 = 首道工序累计开工；合格完成 = 末道累计合格）+ 工序表 + 「报工履历」+ 停工记录。
- **操作**：行内「开工」（填数量/日期）→「完工」（填合格/不良/不良原因）；右上「Excel 报工导入」「下载报工模板」。
- **预期**：
  - 开工被 G1（物料）/ G2（上游可流转）拦截时**给出原因**，并记入停工记录；
  - 完工受 G3（完成 ≤ 开工）约束；
  - 每次申报写入报工履历（只增不改），页面底部可查。

### 5.7 交付管理

- **看什么**：日期链（客户要求完工 → 计划完工 → 系统预计完工 → 实际完工 → 计划发货 → 实际发货）、延期 KPI、风险标识。
- **操作**：「发货登记」填实际发货日。
- **预期**：页头有口径说明；预计完工与实际完工不混用。

### 5.8 异常中心

- **看什么**：页头 `规则摘要（AI 未接入）` 提示、状态 KPI、筛选（类型/状态/等级）、列表、详情。
- **操作**：「重新扫描」；详情内「标记处理中 / 标记已解决 / 关闭异常」，状态变更**必须填说明**；「采纳并记录」只登记建议，不改业务数据。
- **预期**：同一异常重复扫描不重复建单；已关闭不复活；AI 区块区分「已知事实」与「推测」。

### 5.9 基础数据

- **页签**：产品 / 物料 / BOM / 工艺路线 / 工作中心 / 工序适配 / 工作日历 / 计划停机 / 库存 / 到货。
- **操作**：「新增」「编辑」「删除」；「导出当前表」「下载模板」「导入文件」（先「校验」，再「校验并导入」）。
- **预期**：导入错误给**行号 + 字段 + 原因**；主数据按编码**覆盖**、单据**重复即拒绝**；日历可切工作日/节假日；停机影响 HC-03。

### 5.10 统计分析

- **控件**：统计期（起止日期）、产品、工作中心。
- **看什么**：三组 KPI + 明细表（公式/口径）+ 下钻弹窗。
- **预期**：默认统计期与工作台一致（`defaultPeriod`）；分母为 0 显示 `—` 而非 `0.0%`；切换筛选后数字随之变化且可下钻到单据。

### 5.11 全局操作

| 操作 | 位置 | 影响 | 建议 |
|---|---|---|---|
| 切换内置场景 | 顶栏「场景：…」→ 上半天 | **重建整套内置数据**，当前数据被覆盖 | 先备份 |
| 导入外部测试数据 | 顶栏「场景：…」→ 下半「导入外部测试数据」 | 校验通过后覆盖全部数据并刷新；顶栏标识变为文件名 | 先「下载示例数据集」再改；详见 §6.5 |
| 备份 | 顶栏「备份」 | 导出 `生产计划数据备份_YYYY-MM-DD.json` | 测评前、改配置前各做一次 |
| 恢复 | 顶栏「恢复」 | 覆盖当前全部数据，二次确认；与外部导入共用同一套校验 | 用于回滚到基线 |
| 重建演示数据 | 旧数据提示条 | 用当前场景重新生成 | 只在黄色提示条出现时需要；该提示条不会对外部数据出现 |

## 6. 输入数据与预期结果

### 6.1 三套演示数据（固定种子，可复现）

| 场景 | 销售订单 / 生产订单 | 设计意图 | 适合测什么 |
|---|---|---|---|
| 简单 `simple` | 6 / 7 | 物料齐套、每工序单一工作中心 | 跑通主流程、看正常态 |
| 中等 `medium`（默认） | 25 / 27 | 部分缺料、多工序、负荷接近上限 | 缺料与产能冲突 |
| 复杂 `complex` | 80 / 84 | 订单集中、到货延期、部分开工、替代中心、多异常并发 | 压力、异常分类、性能 |

**【重要】数字随「基准日」变化**：系统基准日 = 打开当天（`today()`），演示数据按基准日向前/向后生成。因此：

- **同一天内**重复重建，结果逐字节一致（可复现）；
- **跨天**对比同一场景的指标数字**没有意义**，不要拿昨天的截图当今天的期望值；
- 测评记录必须写明基准日（顶栏可见）。

### 6.2 九张导入表（基础数据页）

| 表 | 类型 | 唯一键 | 必填字段 | 覆盖语义 |
|---|---|---|---|---|
| 产品 | 主数据 | 产品编号 | 产品编号、名称、单位 | 按编码覆盖，保留原 id |
| 物料 | 主数据 | 物料编号 | 编号、名称、单位、类型（`RAW`/`PURCHASE`/`SEMI`） | 按编码覆盖 |
| BOM 明细 | 主数据 | 无 | 产品编号、层级（1/2）、父项编码、子项编码、子项类型、单位用量 | 追加；关联不存在则报错 |
| 工作中心 | 主数据 | 编码 | 编码、名称、产能模式（`DAILY_QTY`/`STD_HOURS`）、日产能或日工时 | 按编码覆盖 |
| 工序与工作中心适配 | 主数据 | 无 | 工作中心编码、工序名称 | 追加；中心不存在则报错 |
| 库存 | 主数据 | 无 | 物料编号、数量（仓库可空，默认「主仓」） | 追加 |
| 采购到货 | 单据 | 无 | 物料编号、数量、预计到货日、是否确认（是/否） | 单据类，重复即拒绝 |
| 销售订单行 | 单据 | 销售订单行号 | 行号、客户、产品编号、数量、客户要求完工日 | 重复即拒绝 |
| 生产订单 | 单据 | 生产订单号 | 订单号、销售订单行号、生产数量 | 重复即拒绝；销售行必须存在 |

**通用规则**：UTF-8 CSV（Excel 可直接打开）或 XLSX（读 sheet1）；逐行校验必填/枚举/数字/日期/关联/文件内重复；**任一行不通过则整批不入库**，并列出前若干条错误（行号+字段+原因）。

### 6.3 报工导入（执行跟踪页）

- 模板列：`生产订单号, 工序号, 日期, 合格数, 不良数, 不良原因`
- 校验：订单存在、工序号存在、日期必填、数量非负，并**校验完成量 ≤ 可完工量**（G3）
- 失败姿态：任一行不通过 → **整批不入库**，弹窗列出行号与原因
- 不良原因取值：`DIMENSION`（尺寸）/ `ASSEMBLY`（装配）/ `INCOMING`（来料）/ `EQUIPMENT`（设备）/ `OTHER`（其他）

### 6.4 可判定的预期结果

| 编号 | 断言 | 预期 | 验证方式 |
|---|---|---|---|
| E-01 | 数量守恒 | 工序 `Σ 日计划量 = 计划量`；下游开工 ≤ 上游合格 | 排程表 vs 任务详情 |
| E-02 | 排产可复现 | 同场景同基准日重复排产结果一致 | 连续两次「执行自动排产」对比 |
| E-03 | 三套策略可区分 | 交付/物料/产能优先产出的计划不完全相同 | 切换策略重排对比 |
| E-04 | 硬约束拦截 | HC-01~05 任一存在时无法「确认计划」 | 构造违规（改期到停机日等） |
| E-05 | 软约束不拦截 | SC-01~05 只提示，仍可确认 | 观察提示徽标 |
| E-06 | 产能口径一致 | 排产结果与 HC-04 判定不矛盾 | 看约束结果表是否 0 处硬约束 |
| E-07 | 约束与顺序无关 | 同一计划多次渲染结论一致（仪表盘与排程页数字相同） | 对比两页「产能冲突」 |
| E-08 | 齐套短板原则 | 整单状态 = 最差物料项状态 | 看齐套明细最差行 |
| E-09 | 三闸门拒绝超量 | 物料不足/上游未流转/完成>开工 均被拒并说明原因 | 手工构造超量申报 |
| E-10 | 报工留痕 | 每次开工/完工/导入都出现在报工履历 | 执行页底部 |
| E-11 | 指标可追溯 | 12 项指标均有公式、口径、明细 | 统计分析明细表 + 下钻 |
| E-12 | 分母为 0 | 显示 `—`，不显示 `0.0%` | 统计期选空区间 |
| E-13 | 异常去重 | 重复「重新扫描」不增加重复单 | 连点两次看总数 |
| E-14 | 版本隔离 | 模拟方案不改变正式计划 | 复制方案→改任务→看正式版本 |
| E-15 | 冻结生效 | 冻结期任务直接改被拒，解冻需原因 | 改 3 天内任务 |

### 6.5 外部测试数据集导入（v1.1 新增）

**入口**：顶栏「场景：…」→ 弹窗下半部分的「导入外部测试数据」。上半部分仍是三套内置场景，两者互不影响。

**步骤**

1. 点「下载示例数据集」，得到 `外部测试数据集模板.json`（1 张待排产订单、2 道工序、主数据齐全）；
2. 按下面契约改成自己的数据；
3. 选择文件 → 自动校验，通过后展示各集合条数与提示，「载入该数据集」按钮才可用；
4. 点「载入」→ 二次确认（显示文件名、订单数、工序数）→ 写入并刷新；
5. 顶栏场景标识变为文件名；订单为「待排产」时，到生产排程页执行自动排产。

**数据契约**

| 规则 | 说明 |
|---|---|
| 必填集合 | `productionOrders`（数组；可为 `[]` 表示只导入主数据） |
| 可选集合 | 产品 / 物料 / BOM / 工艺路线 / 工序 / 工作中心 / 工序适配 / 停机 / 库存 / 到货 / 销售订单与行 / 订单关联 / 计划版本 / 工序任务 / 报修记录等，缺省补空 |
| 顶层信封 | 直接放数据集对象，或包在 `data` / `dataset` / `db` 里（自带备份文件可直接导入） |
| 标量配置 | `settings` / `calendar` / `factory` / `users` 缺省字段自动补齐 |
| 编码解析 | `productCode` / `orderCode` / `workCenterCode` / `materialCode` / `versionCode` 自动解析为 id |
| 版本重连 | 无 `planVersions` 时自动建 `PV-IMPORT` 并激活；`activeVersionId` 缺失/失效时自动修正；`versionId` 缺失或无效的任务改挂工作版本 |
| 校验粒度 | 必填、枚举、数字、日期（含 2 月 30 日这类"格式对但不存在"）、编号重复、关联存在性；错误给 `集合[下标].字段` 定位 |
| 失败姿态 | **任一条错误即整批不载入**，列出前 8 条与错误总数 |
| 规模上限 | 生产订单 ≤ 5000，工序任务 ≤ 20000 |

**与另外两个入口的区别**

| 入口 | 用途 | 是否重建内置数据 | 是否校验字段 |
|---|---|---|---|
| 内置场景 | 快速换一套演示数据 | 是（`buildSeed`） | 不涉及 |
| 导入外部测试数据 | 跑自己的订单/主数据 | 否 | 是（字段级） |
| 恢复备份 | 回滚到某次备份 | 否 | 是（同一套校验） |

**载入后的行为**

| 项 | 行为 | 测评要点 |
|---|---|---|
| 顶栏标识 | 显示文件名或 `datasetLabel` | 不再显示"中等场景" |
| 旧数据提示条 | 不出现（`seedRev` 为空时不判定为旧数据） | 避免被"重建演示数据"误覆盖 |
| 缺计划版本 | 自动建 `PV-IMPORT` 并激活 | 排程/甘特/指标按该版本取数 |
| 缺工序任务 | 订单保持「待排产」，弹窗提示 | 手动排产即可 |
| 任务版本脱链 | 自动改挂工作版本并提示条数 | 修复前此场景下计划页可见 0 条 |

新增断言：

| 编号 | 断言 | 预期 | 验证方式 |
|---|---|---|---|
| E-16 | 外部数据导入后计划可见 | 排程页可见任务数 = 导入任务数（含脱链任务） | 导一份带任务的 JSON，看排程表格 |
| E-17 | 外部数据不被误判为旧演示数据 | 无黄色提示条；顶栏显示文件名 | 导入后看顶栏 |
| E-18 | 导入失败不脏数据 | 任一字段错误时整批不载入，原有数据不变 | 故意改坏一个数量再导入 |

## 7. 关键配置

### 7.1 系统参数（`core/store.js` 的 `settings`）

| 参数 | 默认值 | 含义 | 可改位置 | 影响 |
|---|---|---|---|---|
| `bufferDays` | 2 | 交期缓冲天数 | 代码/数据 | 软约束 SC-03 缓冲不足判定 |
| `freezeDays` | 3 | 冻结周期（天） | 计划版本页右侧 | 范围内任务不可直接改；范围 0~10 |
| `freezeMax` | 10 | 冻结天数上限 | 代码 | 界面输入上限 |
| `materialMode` | `UPDATE` | 主数据导入语义 | 代码 | 主数据按编码覆盖 |
| `dateBasis.scheduling` | `WORKDAY` | 排产日期口径 | 代码 | 排产按工作日 |
| `dateBasis.delayDays` | `CALENDAR` | 延期天数口径 | 代码 | 延期按自然日 |
| `aiEnabled` | `false` | AI 接入开关 | 代码 | 侧栏显示「未接入（规则摘要）」 |

### 7.2 排产策略权重（三桶）

| 策略 | 交付 | 物料 | 产能 | 适用 |
|---|---|---|---|---|
| 交付优先 `DELIVERY` | 60 | 20 | 20 | 交期紧、客户压力大 |
| 物料优先 `MATERIAL` | 25 | 60 | 15 | 缺料多、等料严重 |
| 产能优先 `CAPACITY` | 30 | 20 | 50 | 负荷不均、换线频繁 |

九因素 → 三桶的映射与公式见统计分析页口径说明；**权重是静态可解释的，不是自学习**。

### 7.3 产能模式（两套，无换算层）

| 模式 | 产能池 | 单件占用 | 适用 |
|---|---|---|---|
| `DAILY_QTY` | `dailyCapacity`（件/日） | 1 件 | 节拍稳定、按件计 |
| `STD_HOURS` | `dailyHours`（小时/日） | `stdHoursPerUnit`（小时/件） | 多品种混线 |

排产与 HC-04 共用 `capacityPoolOf` / `capacityDemandOf`，因此两处结论一致——这是本项目的核心防错点，测评时重点验 E-06/E-07。

### 7.4 工作日历与停机

工作日默认周一~周五，可切节假日；工作中心「计划停机」日期不可排产（HC-03）。改日历或停机后，**既有计划不会自动重排**，需要重跑排产——这是已知行为，不是缺陷，但要在测评记录里注明。

## 9. 常见异常与处理方式

| 现象 | 最可能原因 | 处理方式 | 是否缺陷 |
|---|---|---|---|
| 打开是白屏 | 用 `file://` 双击打开 | 起 http 服务，走 `http://127.0.0.1:8099` | 否（浏览器限制） |
| 端口被占用 | 8099 已有进程 | 换端口，**并注意数据不通用**；或结束占用进程 | 否 |
| 顶栏出现黄色提示条 | 本地数据是旧版演示数据（`seedRev` 不一致） | 点「重建演示数据」（先备份） | 否 |
| 「确认计划」灰色不可点 | 存在硬约束 | 看约束结果表，按「去哪看」列修 | 否（设计如此） |
| 开工按钮提交后被拒 | G1 物料不足 / G2 上游未流转 | 看提示原因；补料到货或先完成上游 | 否 |
| 完工提交被拒 | 完成数 > 已开工数（G3） | 修正数量 | 否 |
| 导入弹窗列出一堆行错误 | 整批校验未通过 | 按行号逐条改；整批不会入库 | 否 |
| XLSX 导入报不支持 | 浏览器缺 `DecompressionStream` | 改用 CSV 模板 | 否（有降级通路） |
| 恢复 JSON 失败 | 文件非本系统备份 / JSON 损坏 | 用「备份」导出的原始文件；看报错文案 | 需判断 |
| 页面出现「页面渲染出错」 | 代码或数据异常 | 记下报错文案与控制台堆栈，提 Issue | **是（缺陷）** |
| 选文件后校验不通过 | 字段/关联不符合契约 | 按 `集合[下标].字段` 定位逐条修；整批不会入库 | 否（数据问题） |
| 导入后计划页没有任务 | 数据集未包含工序任务 | 订单为「待排产」，执行自动排产即可；校验提示里已说明 | 否（预期行为） |
| 导入后顶栏仍显示内置场景名 | 使用了「内置场景」而非「导入外部测试数据」 | 走弹窗下半部分导入；载入后标识应为文件名 | 需判断 |
| 导入后出现黄色提示条并"建议重建" | 旧版本（≤0.1.0）的 `seedRev` 判定缺陷 | 升级到 0.1.1；**不要**点重建，否则外部数据被覆盖 | **是（已修复）** |
| 数据"消失" | 换端口/换 host/换 Profile/清缓存 | 用备份恢复；固定测评环境 | 否（架构限制） |
| 保存失败提示存储已满 | localStorage 超限 | 备份后重建场景或清理 | 否（容量限制） |
| 数字与昨天截图不一致 | 基准日变化，演示数据随之变化 | 记录基准日；同日内复测 | 否（设计如此） |
| 排产后改日历/停机，计划没变 | 不自动重排 | 手动重跑排产 | 否（已知行为） |

## 10. 注意事项与风险点

### 10.1 测评注意事项

1. **先定基线再动手**：记录提交号、基准日、浏览器、场景，并导出一份备份。
2. **不要在测试红的情况下往下测**：`npm test` 不过，说明环境或代码已被改动。
3. **用"可判定断言"代替"看起来对"**：优先验 §6.4 的 E-01~E-15。
4. **跨天不要对比数字**：演示数据随基准日生成，隔天数字必然不同。
5. **区分"设计范围外"与"缺陷"**：无权限、无审批、AI 未接入、甘特不可拖拽，都已明示，不计缺陷。
6. **改动前备份**：切换场景、应用版本、恢复 JSON 都会覆盖数据。

### 11.3 约束与指标清单（便于逐条核对）

**硬约束**：HC-01 工序顺序、HC-02 工作中心能力、HC-03 不可生产日期、HC-04 日产能超限、HC-05 下游数量超上游。

**软约束**：SC-01 交期风险、SC-02 负荷不均、SC-03 缓冲不足、SC-04 未确认到料、SC-05 到料晚于计划开工。

**12 项指标**：

| 分组 | 指标 |
|---|---|
| 交付（4） | 订单准时完工率、延期订单数、平均延期天数、准时发货率（内部） |
| 生产（4） | 生产计划达成率、实际产量、工作中心利用率、工序等待时间 |
| 物料（4） | 物料齐套率、缺料订单数、缺料停工次数、到料准时率 |

**异常类型与代码**：物料（物料短缺、物料数量不足、预计到货延期）、产能（超负荷、产能不足、停机影响）、生产（工序延期、产量低于计划、上游延误）、交付（预计完工延期、交期风险、发货延期）。
