## 1. 目标与范围

### 1.1 目标（继承 V1.0 §1.3，不改）

五个目标全部保留：自动排产、物料与产能约束管理、计划调整与方案模拟、计划与执行闭环、交付风险管理。

**本方案补充的一句话验收定义**：PMC 能在系统内独立完成「导入数据 → 建单 → 排产 → 调整确认 → 录进度 → 处理异常 → 看指标」这条线，且每一步的判定依据能被说清、能被复算。

### 1.2 范围（继承 V1.0 §3.2，含三项决策引起的定位调整）

| 维度 | 范围 | 本次决策影响 |
|---|---|---|
| 工厂 / 生产模式 | 单工厂、订单驱动 | — |
| 计划对象 | 生产订单 | 增加「行-单」多对多关联（P-02） |
| 排产粒度 | 工序级、按日 | — |
| 产能模式 | 固定日产能 + 标准工时 | 单位定为 件/日 与 小时/件（P-03），无换算层 |
| 物料分析粒度 | **生产订单级** | 明确不建行级物料池（D-05） |
| 交付管理 | 生产完工 + 发货记录 | 客户承诺止于完工；发货为内部节点（P-01） |
| 生产执行 | 订单级 + 工序级 | 不良增加原因分类维度（D-11） |
| 用户模式 | 单用户，预留账号 | 由 1 人全兼，验收与开发同一人（D-14/D-15） |
| 外部集成 | 预留接口，不对接 | — |
| AI | 异常分析、建议、方案比较 | 不越界改数据；不可用时全线降级 |

### 1.3 明确不做（V1.0 §10 的 21 项 + 本次决策新增的 5 项排除）

继承 §10 全部 21 项。**本次新增排除，防止被误读为"顺便做"**：

| 新增排除项 | 原因 |
|---|---|
| 加班 / 超产能建模 | D-13 定为「硬性最大产能 = 日产能」，不引入加班概念 |
| 运输缓冲与到货日换算 | D-02 交期止于生产完工，运输不建模 |
| 不良品返工回冲 | D-11 只加原因分类，不做返工流程 |
| 行级（销售行）物料池 | D-05 物料按生产订单计算 |
| 已取消订单计入延期统计 | D-07 取消单不计入 |

### 1.4 范围与节奏的关系（重要约定）

D-16 选择「先粗后细」**不构成范围缩减**：所有 V1.0 已列功能仍全部交付，只是**实现顺序上前置一个可运行的粗版本**。原型不进入验收基线，不作为阶段验收对象（§3.1）。

### 2.3 五项「不可粗」的结构性口径（D-16 的护栏）

「先粗后细」只允许在表现层与体验层粗，以下五项一旦近似，后期是结构性返工，不是优化：

| # | 不可粗项 | 一旦粗了的后果 | 必须达到的精度 |
|---|---|---|---|
| 1 | 状态枚举（S-B02） | 跨页筛选错乱，指标分母含混 | 六类状态全枚举，全局唯一编码 |
| 2 | 日期与数量口径（S-B03） | 延期天数算不准，数量对不上 | 日期链与勾稽等式书面化，页面间一致 |
| 3 | 硬/软约束判定（S-A06） | 该拒的没拒，红线失守 | 10 条约束逐条可判定，正反例可测 |
| 4 | 数量守恒（S-A09） | 下游超量流转，报表不可信 | 订单级=工序级汇总，恒等成立 |
| 5 | 指标公式（S-B01） | 同一指标两页两个数 | 12 项指标分子分母与排除规则定稿 |

**允许粗的部分**：配色与排版、甘特图交互细节、辅助面板的信息密度、AI 输出措辞、性能优化、移动端适配（V1.0 未要求）。

### 2.4 三策略权重（D-09 落地，含九因素映射）

**第一步：九因素归桶**（对应 V1.0 §4.4.6）

| 归属 | 因素 |
|---|---|
| 进评分 · 交期桶 | 客户交期紧迫程度、PMC 人工优先级、订单延期时间 |
| 进评分 · 物料桶 | 物料准备情况（齐套/部分齐套/缺料/预计齐套/到货风险） |
| 进评分 · 产能桶 | 工作中心可用产能、工作中心负荷均衡 |
| 进日期推算（不打分） | 预计生产周期、工序等待时间 |
| 进硬性前置（不打分） | 工序前后关系（排程顺序约束，非权重项） |

**第二步：三套权重**

| 策略 | 交期桶 | 物料桶 | 产能桶 | 适用工况 |
|---|---|---|---|---|
| 交付优先 | **60** | 20 | 20 | 交期集中、客户催单多 |
| 物料优先 | 25 | **60** | 15 | 大面积缺料、到货不稳 |
| 产能均衡 | 30 | 20 | **50** | 负荷淤积、部分中心堆积 |

**第三步：可解释性要求**（§9.3 的落地）
每条排产建议必须能回答三件事：① 三桶各得多少分；② 哪个因素把它推到当前位置；③ 若换策略，会上升还是下降。界面以「分项得分 + 命中因素」两列呈现，不做黑箱。

### 2.5 阶段一前冻结的口径包（D-13 落地）

| 项 | 结论 |
|---|---|
| O-01 模块口径 | 按 **9 个模块**计；「计划版本」是生产排程模块内的独立页面，不单列模块 |
| O-03 硬性最大产能 | **= 日产能**，不含加班；超出即硬约束违反 |
| O-04 待生产 / 剩余 | 待生产 = 计划总量 − 已开工量；剩余 = 计划总量 − 合格完成量 |
| O-05 齐套枚举 | 全局唯一：齐套 / 部分齐套 / 缺料 / 预计齐套 / 到货风险 |
| 不良原因枚举 | 尺寸超差 / 装配不良 / 来料不良 / 设备故障 / 其他（五类，可选填） |

**仍待定、已排截止点**：O-02（评分是否共用权重→阶段二 A02 前，默认两套独立）、O-07（计划发货日是否可系统推算→阶段四前，默认仅建议不写入）、O-06（异常三级→阶段五前）、O-08（责任人取值→阶段五前）。

## 3. 实施步骤

### 3.1 阶段 0：垂直切片预演（新增，2~3 周）

**定位**：这是**沟通与验证工具，不是产品阶段**。不改变 V1.0 §11.2 的六阶段定义与顺序，不替代任何阶段，产出不进验收基线。

**目的**：在投入数据层与算法之前，先确认「界面形态 + 数据形态 + PMC 的接受度」三件事对不对，避免按想象做完整套再被推翻。

**范围**：只用最小数据集（1 个产品、3 层以内 BOM、5 道工序、2 个工作中心、5 张订单），走通一条主线：

```
导入最小数据集 → 建 5 张生产订单 → 粗排产（单策略，交付优先）
→ 表格查看 → 改一个工序日期 → 重算 → 看出交期变化
```

**明确不做**：不做甘特图、不做版本与模拟、不做冻结、不做异常、不接 AI、不做统计、不做导出。

**硬性要求（防止原型被误当成品）**：
1. 所有页面顶部显示「**演示态 · 数据与口径未定稿**」横幅；
2. 排产用**已冻结的口径包**（§2.5），不允许为了快而近似；
3. 代码结构须为后续阶段可延续（不做一次性脚手架）。

**Gate 0 通过判据**（3 条，全部满足）：
1. 上述主线可完整跑通，改日期后交期结果正确变化；
2. 有一份「界面与字段清单」确认稿，PMC 认可字段够用、不冗余；
3. 单次排产在 5 张订单规模下响应可接受（主观可接受即可，不设指标）。

> **若 Gate 0 未通过**：说明界面或字段认知有偏差，调整后再进阶段一，**不得带病推进**。

### 3.2 阶段一：数据层与口径冻结（2~3 周）

**任务**
1. 数据库结构落地：§8.1 中 MVP 所需实体，含 factory_id / user_id / created_by / updated_by 预留；**新增「行-单」关联结构**（P-02）。
2. 基础数据 14 类的维护界面与 Excel 双路径导入（P-06：主数据覆盖、单据拒绝）。
3. 十项校验全部生效，错误行给出行号 + 字段 + 原因。
4. 冻结口径包（§2.5）为系统常量与枚举表。
5. 状态枚举总表（S-B02）、日期与数量口径（S-B03）落入代码与文档。

**Gate 1 通过判据**（6 条）
1. 14 类数据中至少 10 类可导入并落库（产品、物料、BOM、工艺、工序、工作中心、适配关系、日历、停机、库存、到货）；
2. 五类错误数据（非法编码、缺必填、无效关联、重复行、类型错）全部被拒并给出行级原因；
3. 重复导入幂等：同文件导两次，数据不翻倍、不产生脏数据；
4. 主数据覆盖更新与单据拒绝两条路径分别可演示；
5. 状态枚举与口径包以单一来源存在，无第二处定义；
6. 追溯矩阵已覆盖 BR-01~BR-24，无空缺。

**回归范围**：导入 → 校验 → 落库全链；重复导入；非法关联拦截。

### 3.3 阶段二：订单、物料与自动排产（3~4 周）

**任务**
1. 销售订单、生产订单、双向行-单关联（关联仅用于追溯与按行汇总）。
2. 优先级评分卡（A02）：六因素进评分、两因素进日期推算、一因素进前置（P-04）。
3. BOM 两级展开与物料需求计算；三类库存口径；五状态齐套判定（A03）；最大可开工（A04）。
4. 物料预留：建议 → PMC 确认 → 扣减其他订单可分配量 → 变更时提示影响。
5. 工艺路线拆工序、双产能模式（P-03 单公式）、工作日历与停机扣减。
6. 候选工作中心推荐（A05）：能力 → 可生产日 → 停机 → 余量 → 交期影响。
7. 三策略自动排产（§2.4 权重）+ 分项得分与命中因素展示。
8. 硬约束判定（A06 的 HC-01~HC-05）+ 软约束风险提示。

**Gate 2 通过判据**（7 条）
1. 从订单 + 基础数据可自动生成排产建议；
2. 三策略在**同一批订单**上产出**可区分的排序与日期结果**（差异可解释，不是随机抖动）；
3. 每条建议可显示三桶得分与命中因素；
4. 同输入同配置连续运行 3 次，结果完全一致（S-C03）；
5. 齐套五状态与最大可开工在至少 6 组构造数据上判定正确（含边界：刚好齐套、差 1 件、到货日=开工日）；
6. 硬约束命中 5 类各至少 1 例被正确识别；
7. 库存不足的订单仍能进计划池并显示风险，且**开不了工**（为阶段四预埋）。

**回归范围**：改 BOM → 重算需求与排产；改产能 → 重算负荷；改日历 → 重算日期。

### 3.4 阶段三：计划调整、版本与模拟（2~3 周）

**任务**
1. 计划表格（精确改单/工序/日期/中心/数量）。
2. 甘特图（任务时间、工序关系、中心负荷）——**允许先粗，只要求与表格数据一致**。
3. 调整辅助面板（替代中心、可调日期、产能余量、系统建议）。
4. 硬/软约束完整检查（含 SC-01~SC-05 与提示四要素）。
5. 正式计划版本：保存、历史查看、版本对比。
6. 情景模拟：复制 → 改优先级/日期/中心 → 比较交付/物料/负荷 → 应用为新版本（旧版保留并标记失效）。
7. 计划冻结：3 天窗口（0~10 可配）、冻结/可改/已解冻三态、解冻必填原因并留痕。

**Gate 3 通过判据**（6 条）
1. 表格与甘特图同一份数据，任一修改两处同步；
2. 硬约束命中时**物理上无法确认**（按钮不可用或保存被拒），不是仅提示；
3. 软约束可保存且风险条目可见、可定位到具体任务；
4. 模拟方案操作前后，正式计划数据快照**完全一致**（BR-17 铁律）；
5. 方案比较可输出交付、物料、负荷三组差异；
6. 冻结期内任务不可直接改；解冻必填原因，记录可查。

**回归范围**：改约束逻辑 → 重测版本确认与模拟；改版本逻辑 → 重测冻结与解冻。

### 3.5 阶段四：生产执行与交付（2~3 周）

**任务**
1. 订单级进度（总量/已开工/已完成/待生产/剩余/预计完工/实际完工）。
2. 工序级进度（计划量/开工量/完成量/合格量/不良量 + **不良原因分类**/工序起止/状态）。
3. 部分数量开工：物料支持多少开多少，其余保持等待（A09 勾稽等式）。
4. 数量守恒拦截：下游不得超过上游合格可流转量；不良不参与流转。
5. 手工录入 + Excel 报工导入（单据类：重复即拒）。
6. 完工登记、发货登记（内部节点）、五类延期识别（A10）。
7. 计划与实际偏差分析。

**Gate 4 通过判据**（7 条）
1. 部分开工可执行：100 件订单在物料支持 60 件时，允许 60 件开工、40 件等待；
2. 下游超量录入被**系统拒绝**（不是提示）；
3. 物料不足时开工被拒；
4. 订单级汇总 = 工序级明细汇总（任意时点抽查 3 单，恒等成立）；
5. 不良数量按原因分类统计正确，且**不进入**下游可流转量；
6. 五类延期（预计/实际生产、计划/实际发货、待发货）识别正确；
7. 错误报工被拒并给出行级原因。

**回归范围**：改工序进度 → 重测数量流转与交付计算。

### 3.6 阶段五：异常与 AI（2 周）

**任务**
1. 四类 13 现象触发识别（A11 映射表）、三级分级、同对象去重合并。
2. 异常记录九字段 + 七步处理闭环。
3. AI 六类辅助（原因分析、影响解释、处理建议、方案比较、策略推荐、风险解释），输出须带数据引用与事实/推测标注。
4. 降级路径：AI 不可用时展示规则结果 + 明确提示，不静默失败。

**Gate 5 通过判据**（5 条）
1. 七类异常场景（§9.6）均能稳定触发，等级正确，关联对象准确；
2. 完成至少 1 次完整闭环：发现 → 分析 → 建议 → 模拟 → 人工决策 → 应用 → 状态更新留痕；
3. 同一异常不重复刷屏（去重生效）；
4. **关闭 AI 后**，排产、物料、执行、交付全部正常（硬性要求）；
5. AI 输出可辨识事实与推测；与系统数据矛盾时主动提示不确定性。

**回归范围**：改异常逻辑 → 重测正式计划版本与情景模拟。

### 3.7 阶段六：工作台、统计与部署（2~3 周）

**任务**
1. PMC 工作台：11 类指标与当日事项，全部可下钻（下钻目标必须在阶段一~五已存在）。
2. 统计分析：12 项指标按口径字典计算，支持时间/订单/产品/工序/中心筛选。
3. 性能记录（S-C06，只测不优化）：50/100/200 订单 × 20/50 中心各跑一次排产并记录耗时。
4. 本地环境整理 + 云端演示部署（§13-11 要求，不可省）。
5. 备份与恢复、部署文档、操作说明、三套测试数据、证据包。

**Gate 6 / 结项判据**（7 条）
1. §13 十五项交付物逐项销项，无「部分完成」；
2. 工作台与统计页同指标同值，每个数字可下钻到业务记录；
3. 本地与云端两套环境均可用，云端可公网访问且有基本访问保护（P09 待定，至少单管理员口令）；
4. 删除数据后可从备份恢复，有演练记录；
5. 按演示脚本完整跑通 §13 最终验收主线；
6. 一名 PMC 从业者（可外部）独立完成一次从导入到看指标的操作；
7. 七日红线全部守住，回归记录齐全。

### 3.8 单人模式的三条执行纪律（P-07，D-14/D-15 的落地）

因为验收人与开发人是同一人，用机制替代独立性：

**纪律一：冷却期复核**
每个 Gate 达成后，**至少隔 24 小时**再做验收复核，用自检清单逐条打勾。理由：当天的自己会记得「本来想怎么做」，从而把「实际做成了什么」看成「打算做什么」。

**纪律二：三项自动化校验（替代人工判断）**

| 校验 | 做法 | 判据 |
|---|---|---|
| 算法可复现性 | 同输入同配置跑 3 次，机器比对输出 | 完全一致 |
| 数量勾稽 | 订单级汇总 vs 工序级明细，脚本比对 | 恒等 |
| 约束拦截 | 构造违规数据，检查是否被拒 | 100% 被拒 |

三项校验每次 Gate 必跑，结果贴入证据包。这三项是单人模式下最不容易自欺的验收。

**纪律三：反例证据**
每个 Gate 必须提交「**系统正确拒绝的 3 个反例**」（如超量流转被拒、硬约束无法确认、AI 不可用仍可排产）。只证明「能做什么」不足以验收，必须证明「不会做什么」。

| 15 小时（业余） | 约 +60%，总区间约 24~34 周 |

### 4.2 缓冲设计

| 位置 | 缓冲 | 理由 |
|---|---|---|
| 每阶段末 | 已含在区间上限内（上限≈基准×1.3） | 单人无并行补位，误差必须内建 |
| 阶段二后 | 额外留 1 周 | 排产是核心，若此处返工，后三阶段全部受影响 |
| 阶段六前 | 额外留 1 周 | 部署与文档常被压缩，但不做则交付不完整 |

### 4.3 时间紧张时的压缩顺序（从先压到绝不压）

**可以先压**：甘特图交互细节 → 辅助面板信息密度 → AI 输出措辞 → 图表美化 → 移动端适配 → 性能优化。

**压缩需谨慎**：工作台指标数（可先上 6 项核心，其余补）→ 异常类型覆盖（先上四类主场景）→ 三套测试数据（先两套）。

**绝不压**：五项不可粗口径（§2.3）、数量守恒、模拟与正式隔离、AI 不越界与可降级、导入校验、备份恢复。

## 5. 资源需求

### 5.1 人力（D-14：1 人全兼）

| 角色 | 承担人 | 时间占比（估） | 主要工作 |
|---|---|---|---|
| 业务/产品（R1+R2） | 你 | 25% | 口径裁决、字段确认、界面走查、验收复核 |

**角色切换的代价要提前认下**：同一天内既写代码又做验收判断，容易把「想做的」记成「做成的」。这是启用冷却期复核的根本原因，不是流程装饰。

**建议的外部补充（低成本、高收益）**：每个阶段末请 1 位 PMC 从业者做 30 分钟走查，只问三个问题——「这个数字你信吗」「你会怎么用这一屏」「哪里你会绕过系统手工做」。这是单人项目最便宜的纠偏手段。

| 本地环境 | 可启动、可持久化、可重建 | 阶段一建立，全程使用 |
| 云端演示环境 | 公网可访问、跨设备、基本访问保护 | 阶段六部署；平台与预算待定（P11） |

| Excel 模板 | 14 类模板 | 阶段一产出，随字段变更同步 |

|---|---|---|---|

## 6. 风险与验收标准

### 6.1 风险清单（单人模式专项 + 继承项合并）

| 编号 | 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|---|
| **RS-01** | **自我验收偏差**：验收人=开发人，把「想做的」当成「做成的」 | 高 | 高 | 冷却期复核（≥24h）+ 三项自动校验 + 反例证据 + 外部 PMC 走查 |
| **RS-02** | **原型被误当成品**：粗版本被拿去演示，暴露口径缺陷 | 高 | 中 | 演示态横幅 + 原型明确不进验收 + 对外演示只用受控数据 |
| **RS-03** | **先粗后细导致口径近似**：为快而在原型里用近似算法 | 中 | 高 | 五项不可粗（§2.3）+ Gate 0 明确要求用冻结口径 |
| **RS-04** | **阶段二返工**：排产是核心，若此处口径或算法返工，后三阶段全受影响 | 中 | 高 | 阶段二后留 1 周缓冲；Gate 2 的复现性校验必跑 |
| **RS-05** | **单人中断**：生病/事务导致 2 周以上停滞 | 中 | 中 | 每阶段结束即封存证据包与文档，保证可接续；不留在半成品状态过夜超过 1 周 |
| **RS-06** | **上下文断裂**：长时间不碰代码后需重新理解自己写的逻辑 | 中 | 中 | 模块卡（S-E03）+ 每阶段一份「当前状态说明」，随代码更新 |
| RS-07 | 范围蔓延（"顺便加个报表/权限"） | 高 | 高 | 变更登记（S-E01）+ §10 护栏比对 + 五条新增排除（§1.3） |
| RS-08 | 数量勾稽断裂（订单级 ≠ 工序级汇总） | 中 | 高 | 自动校验脚本纳入每次 Gate |
| RS-09 | AI 依赖导致降级失效 | 中 | 高 | Gate 5 必做「断 AI」演示 |
| RS-10 | 数据质量拖垮演示 | 中 | 中 | 三套受控数据；演示只用受控数据 |
| RS-11 | 公网演示无保护 | 中 | 中 | 阶段六前定 P09，验收含访问验证 |
| RS-12 | 性能未知（200 订单排产耗时） | 中 | 中 | 先测后定，不在 MVP 承诺优化 |

### 6.2 验收标准（单人模式调整后）

**三级验收保留，执行方式调整**：

| 级别 | 对象 | 执行方式 | 判定人 |
|---|---|---|---|
| L1 模块验收 | 九个模块 | 模块卡 + §9 对应分节 | 自检 + 冷却期复核 |
| L2 阶段门禁 | 七个 Gate（0~6） | 各阶段通过判据（§3）+ 三项自动校验 + 3 个反例 | 自检后冷却复核，签署留档 |
| L3 端到端 | 全系统 | §13 最终验收主线 + 外部 PMC 走查 | 自检 + 外部走查确认 |

**判定规则（沿用评审稿）**

| 判定 | 条件 | 后续 |
|---|---|---|
| 通过 | 全部判据满足，P0 缺陷为 0 | 进下一阶段 |
| 有条件通过 | 一般/轻微缺陷，不影响本阶段核心闭环 | 可推进，缺陷挂账并纳入下阶段回归；**不得跨两个阶段** |
| 不通过 | 阻断/严重缺陷，或任一硬性判据不满足 | 阶段内整改，重提 |

**七条红线（任一失守即判不通过，不因单人而放宽）**

1. 硬约束冲突可被确认；
2. 下游超量流转可被录入；
3. 物料不足仍可开工；
4. 模拟方案影响正式计划；
5. AI 直接修改正式计划、预留或执行记录；
6. AI 不可用导致核心功能不可用；
7. 未校验的导入数据进入排产计算。

### 6.3 结项判据（一次说清）

同时满足以下五条，才算 MVP 完成：

1. §13 十五项交付物逐项销项，每项有 DoD 证据；
2. 七条红线全部守住，有反例证据；
3. 三套测试数据可用，复杂场景能跑通完整闭环；
4. 云端可公网演示，且能演示「断 AI 仍可用」「删除后能恢复」两个动作；
5. 一名 PMC 从业者能独立完成从导入到看指标的完整操作，不需要你在旁解释。
